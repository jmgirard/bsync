## Goal

Make the window grid include every window position that fits in the series, so that runs with `window_increment > 1` no longer drop the last window or abort on a series that holds one window.

## Scope

**In:**
- `build_surface_grid()` (`R/surface.R:94`): the window count becomes `floor((n - window_size - 2 * lag_max) / window_increment) + 1` for lagged estimators and `floor((n - window_size) / window_increment) + 1` for `wgranger()`. The current form, `floor((n - w_max - 2 * lag_max) / window_increment)`, gives the same count when the increment is 1 and can give one window fewer otherwise. The "too short" message states the true minimum, `window_size + 2 * lag_max` (or `window_size`) samples.
- The `synchrony_multiverse()` short-series guard (`R/multiverse.R:474`), which copies the old formula, takes its minimum from the same source as the grid.
- Tests that pin window counts for increments above 1 (for example `test-wphase.R:120-140`) are updated to the new counts.
- NEWS.md entry. The user approved the change in results at the plan gate (CLAUDE.md asks for approval before a change to numeric output).

**Out:**
- The duplicate multiverse cells from the lag cap and the delivered surrogate count per cell: their candidate rows stay. The plan gate chose "drop and announce" for duplicates, and that row records it.
- `pick_optima()` local search with `lag_increment > 1`: its own candidate row.
