# M017: Count every window that fits when window_increment > 1

**Status:** done (2026-10-11, PR #12 https://github.com/jmgirard/bsync/pull/12)

**Goal:** Make the window grid include every window position that fits in the series, so that runs with `window_increment > 1` no longer drop the last window or abort on a series that holds one window.

**Outcome:** `build_surface_grid()` counts `floor((n - window_size - 2 * lag_max) / window_increment) + 1` windows (`lag_max = 0` for `wgranger()`). The old count, `floor((n - window_size + 1 - 2 * lag_max) / window_increment)`, matched at increment 1 and dropped the last window at some larger increments. A new internal helper, `grid_min_length()`, gives the minimum length `window_size + 2 * lag_max` to the grid's "too short" abort and to the `synchrony_multiverse()` short-series guard. The error text now states that minimum (it stated one sample more). Aligned segment designs now get one window per segment. If the segment is longer than `window_size + 2 * lag_max` and the tail holds that many samples, they also get a tail window, which has the same value in every surrogate. `generate_surrogate_segment()` docs, NEWS ("Window grid"), and DESIGN §4.2 state the count. Tests in `test-surface.R`: an explicit-loop sweep (n 1-40, window 2-8, increment 1-4, lag 0-3), an increment-1 regression against the old formula, last-window and minimum-length tests for all four estimators, and segment window tests. `test-multiverse.R` has one-window cells for wcc and wgranger. Updated pins: wgranger rows 16 to 17, wphase case-2 windows 21 to 22, wphase `null_q99` 0.1316320 to 0.1316286, and three multiverse plot snapshots (median ES and tick positions only). Calibration bounds did not move.

**Decisions:** none cross-cutting. The plan gate approved the change in results for `window_increment > 1`.
