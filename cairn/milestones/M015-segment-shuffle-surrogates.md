## Goal

Add an exported segment-shuffling surrogate generator that reorders whole segments of a series in orders drawn uniformly from all orders except the original. Offer it as a `surrogate_method` in `synchrony_multiverse()` and `autotune_wcc()`, with windows that lie inside one segment.

## Scope

**In:**
- `generate_surrogate_segment(y, segment_size, n_surrogates = 100)` in `R/surrogate_generation.R`. It cuts `y` into k = floor(length(y) / segment_size) complete segments from sample 1, the SUSY 0.1.0 convention (tschacher2020). Each column puts the segments in an order drawn uniformly from the k! - 1 orders other than the original, so a segment can stay in place (D-004). Orders are distinct, drawn without replacement. The leftover tail of length(y) - k * segment_size samples stays in place at the end, and the call announces its length.
- `segment_size` is a whole number from 2 to floor(length(y) / 2).
- Up to 8 segments, if `n_surrogates` is at least k! - 1, the call returns every non-identity order and says how many. Above 8 segments, such an `n_surrogates` aborts. If k! - 1 is below 19 (3 segments or fewer), the call warns that no test on these surrogates can reach p <= .05.
- `NA` values move with their segments.
- `"segment"` as a `surrogate_method` value in `synchrony_multiverse()` and `autotune_wcc()` (D-004, RR01 Q4). A segment cell uses segment size s = window_size + 2 * lag_max for `"wcc"` and `"wdtw"`, and s = window_size for `"wgranger"`. Its window increment is s in place of `increment_pct`, and the grid records that increment.
- Segment cells are not crossed with `increment_pct`. The grid holds one segment row per window, lag, and statistic, with `increment_pct` set to `NA`.
- A segment cell with fewer than 4 segments (s above floor(length(y) / 4)) is skipped with a warning that names its window and, for wcc and wdtw, its lag, because it cannot reach p <= .05. A skipped cell stays in the grid with NA results. One message per call states that segment cells use non-overlapping windows aligned to the segments.
- Roxygen with the null this tests (RR01 Q3), the alignment condition per wrapper, the approximate status of `wphase()` segment tests, the tail rule, and the SUSY lineage and departures (RR01 Q5). A `_pkgdown.yml` row, a vignette section, NEWS, `inst/WORDLIST`.

**Out:**
- SUSY-exact segment pairing (a WCC-only statistic over segment pairs i != h): not planned. The first plan gate chose the reordered series, and RR01 confirmed it.
- Orders with no segment in place: rejected by D-004. Cyclic rotations, the exact form that moves every segment, are a candidate row.
- An exact segment test for `wphase()`: candidate row (RR01 rec 7).
- The one-window short count of `build_surface_grid()`: candidate row (RR01 B1).
- A per-cell record of the delivered surrogate count: the docs state it instead (a 4-segment cell uses min(`n_surrogates`, 23) surrogates).
- Pseudo-dyad surrogates in the multiverse: their existing candidate row.

## Decisions

- 2026-10-07 (RR01 Q1, Q5): Segment surrogates draw distinct orders uniformly from all non-identity orders of the k segments, so a surrogate can leave a segment in place. Orders with no segment in place are dropped. They are not a group with the identity, so the test rejects a true null too often at every k. If the segments of `y` are exchangeable, uniform non-identity orders give an exact add-one p-value for every number of surrogates up to k! - 1. A test can reach p <= .05 only with k >= 4.
- 2026-10-07 (RR01 Q2, Q3): A segment test is exact only if every window and every lagged window lies inside one segment. For `wcc()`, `wdtw()`, and `wphase()` this needs `segment_size >= window_size + 2 * lag_max` and `window_increment = segment_size`. For `wgranger()` it needs `segment_size = window_size = window_increment`. `wphase()` stays approximate under alignment, because it takes the Hilbert transform of the whole series. RR01 Q3 states the null for users.
- 2026-10-07 (RR01 Q4): In `synchrony_multiverse()` and `autotune_wcc()`, a `"segment"` cell uses segment size s = window + 2 * lag (s = window for Granger) and increment s, not the cell's `increment_pct`. One matrix is generated per distinct s, and the grid records the increment used. A cell with s above floor(n / 2) is skipped. One message per call says why. The smallest p-value uses the number of columns returned. Rejected: keeping the cell's increment (measured size about 0.065 at .05) and dropping the method from the multiverse (the user asked for it).
- 2026-10-07 (RR01 Q6): The size test uses AR(1) pairs (phi 0.7), window 16, lag 2, segment and increment 20, and 19 surrogates. It runs 1000 pairs at k = 5 and at k = 12 and asserts a rate in [0.03, 0.07]. A control with no-segment-in-place orders at k = 5 must give a rate above 0.07. Unit tests cover k = 3 (all 5 orders) and k = 4. The k = 3 size run of the old AC3 is dropped, because its rate is 0 by construction.
